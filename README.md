# sf-typings

Generate TypeScript declarations for explicitly selected Salesforce objects and local Apex `.cls` files. Requires Go and, for object generation, a locally authenticated Salesforce org alias. Does **not** retrieve records.

```sh
cd sf-typings
go run . -help
go run . -config config.example.json -out generated -snapshots
```

Copy `config.example.json` and set `orgAlias` to your locally authenticated alias; list only the object API names you want. For Apex classes add `"apexSources": ["/path/to/your/sfdx-project/force-app/main/default/classes"]` (a file or recursively scanned directory). Paths in `apexSources` resolve relative to the CLI working directory, not the config file. An Apex-only run can use `{"apexSources":["/path/to/your/classes"]}` without an org alias. At least one object or Apex source is required. `-config` and `-out` are required.

Object generation resolves the alias through pinned `github.com/hacerx/sf-auth-decrypt-go/authdecrypt` v1.0.0 and uses the locally resolved token in memory for direct authenticated REST sObject Describe. It never invokes `sf sobject describe`. This **intermediate token-acquisition** work unit uses the local instance URL when available. If the local token is absent, it obtains only `result.accessToken` from `sf org auth show-access-token -o <alias> --no-prompt --json`. Only when the local org is entirely unavailable does `sf org display --target-org <alias> --json` supply `result.instanceUrl`; its access token is never used. The instance host is validated before any CLI token lookup or REST bearer request. CLI stdout is capped and stderr discarded; failures never expose raw CLI output. This intermediate unit does not retry HTTP 401 or add typed 401 diagnostics; those belong to the final work unit. If credentials are unavailable, the command fails without changing existing output. A valid instance must be HTTPS on a Salesforce host. The CLI rejects redirects, bounds request time and response size, and chooses the highest numeric API version returned by `/services/data/`; it reports credential and transport failures without raw secret-bearing errors. No live org request has verified this intermediate core; the earlier live runs documented in `odd/tasks/sf-typings.md` did not succeed.

`-snapshots` optionally writes the full `Object.describe.json` result (including metadata not represented in the declaration) alongside each `Object.d.ts`. Treat snapshots as potentially sensitive org metadata and keep generated output out of version control as appropriate. The CLI never fetches records. Object and field names are validated; types without a supported mapping become `unknown`. Object properties are optional because a SOQL projection may omit a field; Describe `nillable` additionally allows `null`. Declarations do not guarantee field access or that a query selected a field. Output is prepared only after every Describe succeeds and validates. Snapshot values retain the Describe JSON data, with keys normalized for repeatable output.

Apex generation reads local `.cls` files and emits a `Class.d.ts` with ambient modules such as `@salesforce/apex/Orders.fetch` for parsed `@AuraEnabled` **public/global static** methods. Parameters use an object and returns use `Promise<T>`. String-like, numeric, boolean and `List<T>` types are mapped; unsupported types become `unknown`, not `any`. The class filename must match its declaration; parse failures and duplicate classes fail before generating output. The CLI uses `github.com/octoberswimmer/apexfmt/parser` v0.69.0 (BSD 3-Clause) and the Go ANTLR runtime, not the formatter or Tree-sitter. It builds with `CGO_ENABLED=0`. Include generated files in your LWC project's TypeScript `include` paths. Signatures describe source code, not access rights or arbitrary custom Apex serialization.

Run the public CLI tests with `go test ./...`.
